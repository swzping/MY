# jizhang

## 浏览器记账与 Excel 同步

需要 Node.js 和 Python 3（无需安装 Python 第三方库）。

```sh
npm install
npm run web
```

这个命令同时启动 Expo 网页和仅监听 `127.0.0.1:8787` 的表格同步服务。
浏览器请使用 `http://localhost:8081` 或 `http://127.0.0.1:8081`。
服务也允许 Expo 使用 8082 或旧版 19006 端口。
如果网页已在运行，可另开终端执行 `npm run sync:excel`。

从此版本开始，在浏览器新建的账单会先保存在本机，再按日期从新到旧写入项目根目录的
`history.xlsx` 的“收入”或“支出”工作表。Excel 导入账单不会重复回写；升级前未同步的手动账单会自动加入同步队列。
页面显示同步状态，失败可点击重试；待同步账单保存在浏览器缓存里，
每 30 秒尝试一次，重新打开页面后也会继续。请不要清除浏览器数据，直到同步完成。

写入前自动备份到 `.excel-backups/`。已有账单内容保持不变，目标工作表按日期从新到旧排列，
新增“账单ID”列用于防止同一账单在重复请求时重复写入。
请保留该列；以后从 Excel 导入时，应优先使用该列的 ID，避免与本地账单重复。
Excel 中日期使用记账时选择的日期，未填写的小类、账户和记账人等字段留空。
点击账单可修改，保存后更新 Excel 原账单并重新按日期排序；历史导入账单首次修改时会核对原值并补上账单ID。若表格原值已改变或无法唯一定位，会保留待同步状态，不覆盖。删除操作暂不回写，也不会自动把 Excel 的其他变更加载到页面。

编辑表格与应用记账请分开进行：同步前保存并关闭 Excel/WPS，
避免编辑器内未保存的旧副本覆盖应用新增的行。
如果文件被占用或写入失败，页面会保留待同步状态。

## 验证

```sh
npm test -- --run
npm run typecheck
npm run test:excel
```

Excel 测试在临时副本上运行，不向真实账本写入测试账单。

### 还要存多久

点击首页「累计收支总览」，直接查看近 3 个完整月的月均收入、全部支出和结余。按每月生活费 1000／2000／3000／5000 元，展示目标本金与还需存钱的时间。

目标本金按假设年净收益率 1.2% 计算；还需月数＝（目标本金−现有存款）÷月均结余，向上取整，不计复利或通胀。现有存款默认取非负累计账面结余，可临时改为真实存款；账面结余不等于资产余额。月均结余不为正时不预测未达标目标的日期，缺少月份会提示。原财务资料保留，但复杂资产管理页面不再作为首页入口。
