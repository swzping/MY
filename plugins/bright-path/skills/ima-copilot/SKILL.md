# IMA Copilot

这个技能让 Bright Path 在需要外部知识库支持时，优先通过 IMA Copilot MCP 服务查询资料，再把结果整理成可用结论。

## 使用前提

本机需要已经启动 IMA Copilot MCP 服务，并监听：

```text
http://127.0.0.1:8081/mcp
```

如果 MCP 工具不可用，先说明连接不可用，并提示用户检查 `references/ima-copilot-setup.md` 中的启动步骤。不要编造知识库结果。

## 何时使用

在这些场景使用：

- 用户说“查 IMA”、“问 IMA Copilot”、“查询我的知识库”。
- 用户的问题明显依赖个人知识库、历史资料、收藏文档或团队资料。
- Bright Path 的整理、计划、复盘、决策需要事实依据，而当前上下文不足。

不要在这些场景使用：

- 用户只是要普通头脑风暴或个人反思。
- 用户没有要求查询知识库，且当前上下文已经足够回答。
- 查询会暴露敏感信息而用户没有明确授权。

## 工具选择

如果 MCP server 暴露 `ask`：

- 用于单知识库模式。
- 参数只传 `question`。

如果 MCP server 暴露 `ask_with_kb`：

- 用于多知识库模式。
- 参数包含 `question` 和 `knowledge_base_id`。
- 如果用户没有给知识库 ID，先问一个简短问题确认目标知识库。

## 提问方式

向 IMA 提问时，问题要具体、可检索、少含情绪判断。

优先使用这种格式：

```text
请基于知识库资料回答：
主题：
我需要：
输出要求：
```

## 输出方式

查询后，用中文输出：

```text
知识库结论：
依据：
不确定点：
下一步：
```

如果结果用于 Bright Path 的主流程，可以再压缩成：

```text
可用于当前问题的资料：
对计划/决策的影响：
建议下一步：
```

## 边界

- 明确区分“知识库返回内容”和“自己的推断”。
- 不把 IMA 查询结果包装成确定事实，除非资料本身足够明确。
- 不输出 cookie、token、bkn 等认证信息。
- 不在回答中要求用户粘贴敏感认证信息；只提醒用户在本机环境变量中配置。
