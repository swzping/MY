# Skills 笔记

一句话解释：`Skill` 是给 AI agent 的可复用能力包，通常包含任务说明、工作流程、检查清单、参考资料、模板和脚本，让 AI 在处理某一类任务时更稳定。

## Skill 解决什么问题

Skill 主要解决“怎么做一类任务”的问题。

如果只是告诉模型一句“帮我写报告”，每次结果可能很不稳定。Skill 可以把长期经验沉淀下来：

- 什么场景触发这个 Skill。
- 先做什么，后做什么。
- 需要读取哪些参考资料。
- 应该调用哪些脚本或工具。
- 输出格式是什么。
- 完成前怎么检查。
- 哪些风险必须提醒。

它更像一个给 Agent 用的 SOP，不只是一个 prompt。

## Skill 适合放什么

| 内容 | 例子 |
| --- | --- |
| 触发条件 | 用户说“生成日报”“代码审查”“技术分析股票”时使用 |
| 工作流程 | 收集资料、分析、生成、验证、交付 |
| 检查清单 | 是否有来源、是否跑测试、是否渲染检查 |
| 模板 | Markdown、Word、PPT、报告结构 |
| 脚本 | 数据抓取、格式转换、渲染、测试 |
| 参考资料 | 风格指南、API 说明、领域知识 |
| 禁止事项 | 不给投资建议、不提交密钥、不跳过验证 |

## 什么时候写 Skill

适合写 Skill 的信号：

- 某类任务经常重复。
- 输出质量依赖流程，而不只是模型能力。
- 有固定格式或验收标准。
- 需要绑定模板、脚本或参考资料。
- 希望多个项目或多次对话都能复用。
- 任务不是简单函数调用，而是带判断、步骤和质量控制。

例子：

- 文档生成与视觉检查。
- 股票技术分析。
- 每日新闻趋势复盘。
- 前端设计工作流。
- 代码审查流程。
- 创建项目模板。

## 什么时候不要写 Skill

下面情况不一定需要 Skill：

- 一次性任务。
- 一个普通脚本就能完整解决。
- 任务步骤还没稳定。
- 只是封装一个 API 调用。
- 没有可复用的流程、模板或检查标准。

如果只有“调用某个系统”的需求，通常先考虑脚本或 MCP；如果有“按某种方法完成任务”的需求，再考虑 Skill。

## Skill 和 prompt 的区别

| 对比 | Prompt | Skill |
| --- | --- | --- |
| 生命周期 | 一次性或短期 | 长期复用 |
| 内容规模 | 通常较短 | 可以包含多文件、模板、脚本 |
| 适用范围 | 当前对话 | 多个任务或项目 |
| 重点 | 指令 | 方法、资源、验证 |
| 可维护性 | 容易散落 | 可以版本化和迭代 |

好的 Skill 不是把长 prompt 放进文件，而是把完整工作方法整理成可执行、可检查的包。

## Skill 和 MCP 的区别

| 问题 | Skill | MCP |
| --- | --- | --- |
| 这个任务应该怎么做？ | 是 | 否 |
| 要按什么流程和标准输出？ | 是 | 否 |
| 如何调用外部系统？ | 间接 | 是 |
| 如何统一暴露工具给多个客户端？ | 否 | 是 |
| 权限和认证在哪里做？ | 不应该主要靠 Skill | MCP server / 外部系统 |

例子：

- Skill：告诉 Agent 如何做 A 股隔夜策略复盘。
- MCP：提供行情、公告、研报、交易账户查询等工具接口。

## Skill 和 LangGraph 的区别

Skill 是方法包，LangGraph 是流程运行时。

Skill 可以是自然语言和脚本组合，强调让 Agent 知道“应该怎么工作”。LangGraph 是代码框架，强调让系统“按图执行”。

当流程简单时，Skill 足够。流程复杂、需要状态、分支、循环、恢复时，可以把 Skill 里的方法转成 LangGraph。

## 一个好 Skill 的结构

```text
my-skill/
  SKILL.md
  references/
    style-guide.md
    domain-notes.md
  templates/
    report.md
  scripts/
    render.py
    validate.py
```

`SKILL.md` 应该包含：

- 名称和描述。
- 什么时候使用。
- 输入需要什么。
- 工作步骤。
- 需要读取哪些参考资料。
- 可以调用哪些脚本。
- 输出格式。
- 验证清单。
- 风险与边界。

## 设计建议

- 触发条件要清楚，不要写成“任何 AI 任务都使用”。
- 步骤要能执行，不要只有抽象原则。
- 检查清单要具体，例如“渲染 PDF 并查看页面 PNG”，比“保证质量”更有用。
- 模板和脚本尽量放进 Skill 包，而不是只写外部链接。
- 高风险领域要写清边界，例如医疗、法律、金融、生产系统操作。
- Skill 不要替代权限控制，尤其不能靠一句“不要做危险操作”来保护系统。

## 适合个人沉淀的 Skill 类型

- 学习复盘 Skill：每天把学习材料整理成概念、判断和行动。
- 新闻趋势 Skill：按事实、机制、影响、行动四层整理新闻。
- 项目启动 Skill：生成 README、AGENTS.md、目录结构和验证命令。
- 代码审查 Skill：按风险、复现、测试缺口输出。
- 数据分析 Skill：固定数据读取、清洗、图表和结论格式。
- 股票研究 Skill：固定数据来源、技术面、资金面、风险提示和复核方式。

## Skill 案例记录

这里记录值得观察或可能安装试用的 Skill。重点看它们沉淀了什么工作方法，而不是只看名字。像 `Hermes Agent` 这类完整智能体框架，主记录放在 [Agent 工程总览](agent-engineering.md)，这里仅保留和 Skill 机制相关的交叉引用。

| Skill | 一句话理解 | 适合学习 | 注意事项 |
| --- | --- | --- | --- |
| claude-mem | 给 Claude / coding agent 使用的记忆类 Skill 或记忆工作流 | 跨会话上下文、项目记忆、历史决策检索 | 记忆内容可能含敏感信息，要关注删除、过期和隐私边界 |
| Agent-Reach | 给 agent 增强互联网/平台触达能力的 Skill | 搜索、读取网页和平台内容、工具路由 | 平台接口和登录状态易变，要保留来源并注意合规 |
| GitNexus | 帮 agent 理解 Git 仓库和代码关系的 Skill | 代码库索引、结构理解、影响分析、Graph RAG 思路 | 静态分析不一定覆盖动态语言和框架魔法，结果要人工复核 |
| Humanizer-zh | 中文文本 humanizer / 去 AI 味 Skill | 中文写作润色、AI 痕迹识别、语气自然化 | 不应用于学术造假、虚假署名或规避平台检测 |
| Hermes Agent | Skill-native 自改进 agent 框架，非单个 Skill | skills 作为 procedural memory、自动创建/改进 skills | 主分类是智能体框架，权限和供应链风险更高 |

### claude-mem

一句话解释：`claude-mem` 可以理解为记忆类 Skill / 工作流，目标是让 Claude 或 coding agent 在不同会话之间保留项目背景、历史决策、调试经验和用户偏好。

适合观察：

- 它如何把长会话拆成可检索的 observation，而不是简单保存全部聊天记录。
- 它如何区分项目事实、用户偏好、历史决策、临时状态。
- 它是否支持搜索、摘要、时间线、删除和过期。

学习价值：

- Agent 记忆的关键不是“记得越多越好”，而是“需要时能找到正确的旧信息”。
- 对 coding agent 来说，记忆可以减少重复解释项目结构、历史坑点和个人偏好。
- 记忆系统最好和 `AGENTS.md`、项目 README 分工：稳定规则写进项目文件，个性化和历史上下文放记忆层。

风险与注意：

- 记忆里不要长期保存密钥、隐私数据、客户数据或未经确认的推测。
- 旧记忆可能和当前代码状态冲突，需要有更新时间和置信度意识。
- 最好有查看、编辑、删除和清空机制。

### Agent-Reach

一句话解释：`Agent-Reach` 可以理解为给 agent 增强互联网触达能力的 Skill，让 agent 更方便地搜索、打开、读取和整理外部平台内容。

适合观察：

- 它支持哪些平台和内容类型。
- 它如何处理网页、社媒、视频、GitHub、文档等不同来源。
- 它是否有来源保留、失败回退、限流处理和登录状态说明。

学习价值：

- “联网能力”不是一个单点能力，而是一组搜索、读取、解析、引用和验证流程。
- 适合整理成研究类 Skill：先搜，再筛，再读原文，再记录出处。
- 对趋势研究、开源项目观察、竞品分析很有价值。

风险与注意：

- 平台抓取和登录可能触发风控，要注意平台条款。
- 外部内容可能过期、被删、被改或带偏见。
- 重要结论要保留 URL、日期和来源类型。

### GitNexus

一句话解释：`GitNexus` 可以理解为代码库理解类 Skill，帮助 agent 从 Git 仓库中提取结构、依赖、调用关系和影响范围。

适合观察：

- 它如何索引仓库结构、文件关系、函数调用和依赖图。
- 它是否能辅助回答“改这个文件会影响哪里”。
- 它如何和 MCP、Graph RAG 或本地代码搜索结合。

学习价值：

- Coding agent 不能只靠逐文件阅读，大型项目需要结构化地图。
- 代码图谱、影响分析、依赖路径能帮助 agent 在动手前判断风险。
- 这类 Skill 适合沉淀到项目启动、代码审查和重构流程里。

风险与注意：

- 静态分析可能漏掉运行时注入、配置驱动、框架约定和动态调用。
- 代码图谱是辅助判断，不是最终真相。
- 对大仓库要关注索引速度、缓存更新和结果可解释性。

### Humanizer-zh

一句话解释：`Humanizer-zh` 是中文文本润色类 Skill，用来识别和减少 AI 写作痕迹，让文字更自然、具体、有个人表达。

适合观察：

- 它总结了哪些中文 AI 写作常见痕迹。
- 它如何改写空泛句、对称句、营销腔、机械总结和过度连接词。
- 它是否能保留事实和作者意图，而不是只做风格替换。

学习价值：

- 中文写作的 humanizer 不是简单“口语化”，而是恢复具体信息、节奏变化和真实判断。
- 适合用于知识笔记、文章初稿、产品文案和社媒内容的二次编辑。
- 可以拆成四步：识别 AI 痕迹、保留事实、改写表达、人工复核。

风险与注意：

- 不应该用于学术造假、虚假署名、规避检测或批量生产低质内容。
- 如果原文事实错了，润色只会让错误更像真的。
- 正式发布前仍要人工确认事实、语气、引用和责任边界。
