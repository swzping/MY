# Daily Self Review Framework

## Analysis Lenses

Use these lenses selectively. Do not force all of them into the final answer.

### Codex Usage Behavior

When reviewing Codex history, look beyond the literal questions. Analyze how the user collaborates with the agent:

- What they delegate to Codex: coding, research, planning, reflection, memory, automation, design, debugging, document work
- How they steer Codex: corrections, screenshots, examples, direct feedback, skill mentions, constraints, desired tone
- How they use evidence: asking for verification, showing screenshots, referencing files, requiring history inspection
- How they build leverage: creating skills, templates, scripts, memories, reusable workflows, personal systems
- Where loops appear: repeated clarification, vague starting prompts, missing source material, tool mismatch, overbroad scope
- Where agency appears: challenging poor assumptions, refining the workflow, turning one-off tasks into durable assets

Codex-specific optimizations:

- For behavior reviews, explicitly say "use today's local Codex history" instead of relying on a single current request.
- Start broad tasks with a target output: "Give me a 1-page review with 3 optimizations and 3 assets to distill."
- When correcting Codex, say what assumption was wrong and what evidence source should be used next time.
- Convert repeated Codex usage into skills, prompt templates, or checklists.
- Ask Codex to separate "observed behavior" from "interpretation" for reflective tasks.

### Question Quality

Look for whether questions are:

- Clear about the desired outcome
- Specific about constraints and context
- Asking for a decision, a plan, an explanation, or emotional support
- Repeating because the answer was not captured into a reusable form
- Too broad, too abstract, or missing examples
- Improving through iteration

Suggested optimization language:

- "Turn broad asks into sharper briefs: goal, context, constraints, output format."
- "When a question repeats, convert it into a checklist or saved prompt."
- "When you feel stuck, ask for the smallest next observable action."

### Work And Learning Patterns

Look for:

- Topics the user returns to voluntarily
- Tasks that create momentum
- Tasks that create avoidance, overthinking, or repeated clarification
- Whether the user learns better through examples, plans, conversation, artifacts, or experiments
- Whether the user prefers breadth first or depth first

Possible conclusions:

- Strength: curiosity, systems thinking, taste, persistence, reflection, speed of iteration, emotional honesty, pattern recognition
- Gap: capture discipline, prioritization, verification, narrowing scope, asking for examples, decomposing large goals, protecting focus

### Emotional And Motivational Signals

Look for:

- Reassurance-seeking loops
- High standards that help quality but slow action
- Desire for companionship, accountability, or clearer structure
- Topics that carry hope, anxiety, identity, pride, or shame

Use careful language:

- Say "the evidence suggests" rather than over-diagnosing.
- Avoid clinical labels.
- Treat emotion as useful signal, not a flaw.
- Recommend environmental supports before telling the user to try harder.

### Strengths And Compensations

For each strength, suggest how to amplify it.

For each weakness or friction point, suggest a compensation system:

- Forgetting -> capture template, daily inbox, review ritual
- Overthinking -> decision deadline, criteria, reversible/irreversible label
- Broad curiosity -> parking lot, theme of the week, limited active projects
- Perfectionism -> versioned outputs, "good enough for next step" definition
- Context switching -> batching, visible queue, start/stop ritual
- Vague goals -> outcome statement, done definition, examples

### Distillation Targets

Recommend assets when repetition appears:

- Prompt template: repeated way of asking for help
- Checklist: repeated quality gate or workflow
- Decision rubric: repeated choice or tradeoff
- Personal principle: repeated value or preference
- Learning map: repeated domain of study
- Project memory: facts and decisions worth preserving
- Automation: repeated mechanical task
- Skill: repeated workflow that Codex should perform consistently

For each asset, provide:

1. Name
2. Trigger
3. Why it matters
4. First draft or next step

## Default Output Details

### Today In One Sentence

Compress the day into a meaningful but grounded sentence:

"Today looked like a day of turning scattered questions into systems for clearer execution and more honest self-understanding."

### Question Patterns

Cluster the evidence. Good clusters often look like:

- "Execution questions"
- "Understanding questions"
- "Self-improvement questions"
- "Tooling and workflow questions"
- "Creative exploration questions"
- "Codex collaboration corrections"
- "Reusable system building"

For each cluster, mention:

- What the user was trying to get from the assistant
- What this reveals about current priorities
- Whether the pattern is useful, costly, or ready to be systematized

### Optimizations

Prefer actions for tomorrow:

- Start each session with "what result do I want by the end?"
- End repeated threads by saving a template or note.
- Ask for a checklist when quality matters.
- Ask for one concrete next step when energy is low.
- Split reflective questions from execution questions so neither gets diluted.
- For daily Codex behavior reviews, ask Codex to inspect today's history before concluding.
- When a response disappoints you, update the responsible skill instead of only correcting the single answer.

### Growth Plan

Use three horizons:

- Daily: one 5-15 minute practice
- Weekly: one review ritual
- 30-day: one theme or measurable experiment

Make the plan humane. Avoid overloaded plans.

## Guardrails

- Do not pretend to know the whole person from one day.
- Do not moralize productivity.
- Do not turn every weakness into a defect; often it is an unsupported strength.
- Do not produce generic life advice when concrete evidence is available.
- Do not recommend too many changes at once.
- Do not end with vague encouragement only; end with one clear next action or reflection.
