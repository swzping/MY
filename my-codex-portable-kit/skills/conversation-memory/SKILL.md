# Conversation Memory

## 概览

从历史 Codex 对话中生成一份简洁、可追溯的记忆备忘录，并额外生成一段可直接复制到新会话或另一台电脑使用的续聊提示词。

把备忘录视为 `.codex` 原始历史之上的第二层记忆：它负责提炼、组织和标注出处，不替代原始记录。保留足够溯源信息，方便未来需要时回到原始会话。

## 工作流程

1. 仅在必要时澄清范围：主题、日期范围、会话标题、项目、压缩深度。
2. 涉及本机 `.codex` 历史时，优先用 `scripts/extract_codex_threads.py` 定位候选会话。
3. 只阅读必要的导出材料或源文件。避免把大段原始日志塞进上下文。
4. 按 `references/memo-schema.md` 写备忘录。
5. 每次都必须包含 `续聊提示词`，并保证它可以在另一台电脑独立使用。
6. 用户要求保存文件时，优先保存为 Markdown。

## 用法与用例场景

用户可以直接用自然语言调用本技能。遇到范围不清时，先用最少问题确认主题或时间范围。

常见用法：

```text
使用 $conversation-memory 整理最近关于 Codex 插件和技能迁移的历史对话，生成备忘录和续聊提示词。
```

```text
使用 $conversation-memory 找一下我之前关于 002178 尾盘策略的讨论，整理成可追溯备忘录。
```

```text
使用 $conversation-memory 把 2026-06-15 到 2026-06-23 之间关于 app-guardian 推送跳转的问题压缩成 deep 版本，并给我换电脑后继续讨论的提示词。
```

```text
使用 $conversation-memory 根据线程 ID 019ef207-a755-7191-85ac-615b3782b1d1 生成一份 standard 备忘录。
```

典型场景：

- `换电脑继续讨论`：生成自包含的续聊提示词，让新设备没有 `.codex` 原始记录也能继续。
- `历史问题复盘`：把一个项目、股票策略、法律问题、工具配置等跨多轮讨论整理成可读结论。
- `找回上下文`：根据关键词、日期、会话标题或线程 ID 找出相关历史对话。
- `沉淀个人偏好`：提取用户已经表达过的偏好、约束、拒绝过的方案。
- `继续未完成任务`：保留未解决问题、下一步动作和相关文件路径。

## 历史来源选择

优先级如下：

1. `~/.codex/session_index.jsonl`：查会话 ID、标题、更新时间。
2. `~/.codex/sessions/**/rollout-*.jsonl` 和 `~/.codex/archived_sessions/*.jsonl`：查原始会话事件。
3. `~/.codex/logs_*.sqlite`：仅在 JSONL 来源缺失或不足时使用。
4. `~/.codex/memories_*.sqlite`：仅在用户明确询问产品内置记忆状态时使用。

不要把 `.codex` 内部格式当成稳定 API。解析失败时，先检查小样本，再保守适配。

## 提取脚本

常用命令：

```bash
python3 /Users/edy/.codex/skills/conversation-memory/scripts/extract_codex_threads.py --query "主题关键词" --limit 5 --out work/conversation-memory
```

常用参数：

- `--codex-home PATH`：指定 `.codex` 目录，默认 `~/.codex`。
- `--query TEXT`：搜索会话标题和清洗后的对话文本。
- `--since YYYY-MM-DD` 和 `--until YYYY-MM-DD`：按会话更新时间过滤。
- `--thread-id ID`：导出指定会话。
- `--include-archived`：包含归档会话，默认开启。
- `--max-chars N`：限制每个会话导出的最大文本量。

脚本只读 `.codex`，不会修改历史记录。它会把导出的 `.md` 文件和 `index.json` 写到输出目录。

## 备忘录规则

写备忘录或续聊提示词前，阅读 `references/memo-schema.md`。

保持忠实和可追溯：

- 分清事实、决策、偏好、假设、未解决问题。
- 不确定的信息要标注不确定，不要为了流畅而补全。
- 保留关键日期、会话标题、线程 ID、源文件路径、相关项目路径。
- 避免长篇复制原始对话。应总结，并引用来源会话。
- 不写入密钥、token、cookie、私钥、密码等敏感信息。源材料中出现时要脱敏。

## 续聊提示词规则

每次调用技能都必须输出一段可携带的续聊提示词，即使没有保存文件也要输出。

续聊提示词要告诉未来的 Codex：

- 正在延续什么主题。
- 已经建立了哪些背景和结论。
- 哪些用户偏好、决策或约束需要保留。
- 还有哪些未解决问题。
- 如果有，源备忘录、原始会话标题、线程 ID、日期在哪里。
- 用户下一步大概率想继续做什么。

续聊提示词要足够自包含。换电脑后即使没有原始 `.codex` 文件，也能凭这段提示词继续讨论；线程 ID 和源路径只作为可选溯源线索。
