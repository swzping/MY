# 备忘录模板

使用本模板生成历史对话记忆。保留有价值的章节；确实为空的章节可以省略。

## 记忆备忘录

```markdown
# 历史对话记忆：<主题>

生成时间：<本地日期时间>
整理范围：<主题、日期范围、线程 ID 或搜索关键词>

## 一句话摘要
<用一句话说明这段历史记忆最值得保留的内容。>

## 背景
<当时为什么讨论这个主题，用户想解决什么问题。>

## 已建立的上下文
- <后续讨论应该继承的事实、前提、背景。>

## 决策与偏好
- <用户已经做出的选择、稳定偏好、接受或排除过的方案。>

## 关键推理
- <以后重新推导会比较费劲、值得保留的推理过程。>

## 产物与引用
- <文件、路径、URL、命令、输出、生成文档或交付物。>

## 未解决问题
- <还没解决的问题、待验证假设、下一步决策点。>

## 建议下一步
- <可以继续推进的具体方向。>

## 溯源
- 会话：<标题> | <线程 ID> | <更新时间>
- 来源：<源文件路径>
```

## 续聊提示词

续聊提示词必须可以直接复制到新会话使用，包括在另一台电脑上使用。它不能依赖原始 `.codex` 文件一定存在。

```markdown
## 续聊提示词

请基于以下上下文继续之前的讨论：

主题：<主题>

已经建立的上下文：
- <可携带的上下文摘要>

需要保留的决策和用户偏好：
- <决策、偏好、约束>

未解决问题 / 下一步想探索：
- <开放问题和下一步>

可选溯源信息：
- <会话标题、日期、线程 ID、备忘录文件名、源路径>

请从这个状态继续，不要从零开始。如果这台电脑上没有相关源文件，请先依据上面的上下文继续；只有在确实缺少关键材料时，再向用户索要具体文件或信息。
```

## 压缩层级

- `brief`：一句话摘要、3 到 5 条上下文、续聊提示词。
- `standard`：默认层级，包含主要章节，短小但足够继续讨论。
- `deep`：包含时间线、考虑过的替代方案、更细的溯源信息。

除非用户另有要求，默认使用 `standard`。

## 隐私与脱敏

写入备忘录前脱敏以下内容：

- API key、bearer token、cookie、私钥、密码。
- 对溯源没有必要的长串不透明 ID。
- 与主题无关的个人信息。

不要编造信息填满章节。缺失或不确定时，直接标注“不确定”或“未在来源中找到”。
